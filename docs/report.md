## 1. Where the project actually stands

The project asks one question before it is allowed to build anything: **can a
benign-looking input stream measurably corrupt a TTT-E2E model's fast weights?**
Dossier §7 makes it a hard kill-gate — no demonstrated attack means no defense
worth building, and STOP is a complete, acceptable outcome.

That question has **not** been answered, and cannot be yet. What has changed is
that the machinery to answer it now exists, is tested, and several ways of
answering it *wrongly* have been found and closed.

## 2. What was built this period

Nine reviewable branches, in dependency order. Each has its own commit message
with the reasoning; this is the summary.

### `eval/fast-weight-carry` — the overlay the experiment could not run without

`src/trustgate/eval/carry.py` + ADR-006. Threads adapted fast weights across
inner-loop chunks *and* across sequence boundaries, which the vendor cannot do at
all. `step_fn` is the single injected seam; the chunk loop, carry threading,
optimiser-state threading and step accounting are all ours and CPU-tested with no
checkpoint.

### `attack/objectives-masked-ce` — the attacker optimises the victim's own metric

`src/trustgate/tokens.py`, `src/trustgate/eval/lm_loss.py`, and the two objective
bodies. `masked_mean_ce` transcribes the vendor's `cross_entropy_loss_and_accuracy`
(`loss.py:6-29`) rather than importing it, because the vendor is not importable in
the CPU environment by design. Mean CE in nats over *valid* positions.
`degrade_loss` returns the negation so every caller minimises; `trigger_loss` is
trigger CE + `stealth_weight` × benign CE.

### `attack/token-corpus` — spans of real text, in ID space

`src/trustgate/attack/corpus.py` + ADR-007. The corpus store is duck-typed on
`len()` and slicing, so the real zarr `/val` array drops in unchanged and `zarr`
is never imported. Spans are BOS-free and the sampler raises rather than
substituting. Records the three unmatched structural variables the arms would
otherwise differ on silently: provenance (offsets, mean gap), multiplicity, and
baseline NLL via an injected scorer.

### `attack/select-stream` — the constrained proposal generator

`build_select_stream`, `build_benign_control`, plus two reported-but-not-gating
arms (difficulty-matched control, contiguous single-slice). Not a search:
adversarial choice and ordering is `craft_stream`'s job (T1.9), which drives it
through `order_fn`. The window `+1` convention is explicit and asserted, and the
extra token is real contiguous corpus text rather than padding.

### `eval/run-condition-matching` — seven fields the matching discipline needed

`dtype`, `span_tokens`, `n_chunks`, `valid_tokens`, `stream_corpus_split`,
`eval_tokens_sha256`, `inner_lr_multiplier`. Validation lives in `__post_init__`
rather than at comparison time, because two runs that both left a field unset
would *match* each other — precisely the failure the class exists to prevent.

### `eval/thresholds-and-report` — the bars, the report, and the CLI

`src/trustgate/eval/prereg.py` holds the three frozen bars as constants with a CI
test that parses `PREREGISTERED.md` and asserts equality. `python -m
trustgate.eval.harness` now exists with exactly the flags
`experiments/001-attack-spike/README.md` had documented since the scaffold.
`run_attack_spike` is implemented with injectable seams and **writes no report** —
its own contract says it does not decide go/no-go.

### `docs/prereg-scope-and-ambiguities` — decisions made before any number exists

Verdict scope, fluency aggregation, measurement mode. Details in §4.

### `infra/ci-cpu-tests` — CI, and three review checks mechanised

`.github/workflows/ci.yml`; there was no `.github/` at all. Runs the CPU suite on
3.11 and 3.13, does **not** check out the unlicensed vendor submodule, and a
second job enforces three checks the protocol calls non-negotiable but which were
enforced only by a human remembering to look.

### `eval/fluency-reference` — the third gating bar

`src/trustgate/eval/fluency.py`, `gpt2_reference.py`, three scripts, and
`FLUENCY_REFERENCE.md`. Details in §5.

## 3. The findings that changed what would otherwise have been done

This is the part of the report that matters most. Each of these was found at the
desk, for zero spend, and each would have cost a paid GPU run or a wrong verdict.

### 3.1 The vendor discards the adapted fast weights — a guaranteed false STOP

`ttt/model/transformer.py:712` binds the scan carry and line 745 returns
`loss, metrics` only. The carry holds `new_model` — the adapted prime MLP, which
*is* the fast weights. Line 685 also rebuilds the model from outer params with a
dtype cast on every call, line 686 re-initialises the inner optimiser state, and
`loop.py:160` vmaps the whole thing over the batch.

`run_stream` was logged as blocked on checkpoints. It was blocked on an **API
gap**. The obvious two-call harness — adapt on the poison stream, then measure
benign loss — resets the fast weights between the calls and measures eval noise.
That is a *structurally guaranteed null*: a STOP verdict indistinguishable from a
real one. Since STOP ends the project, this defect would have converted a paid
GPU run into a project-ending artefact, silently.

Resolved by an overlay (ADR-006), ADR-002-compatible, CPU-tested.
`test_step_receives_previous_output_not_initial_weights` is the tripwire.

### 3.2 A second, independent route to the same false STOP

`get_ilr_multiplier` (`transformer.py:564-573`) ramps the inner learning rate off
`state[step_index]`, and `train.py:224` pins `step_index` high in eval mode
specifically so the ramp saturates. A hand-rolled harness leaving it at 0 runs a
near-frozen inner loop. Closed by `assert_saturated_inner_lr` and recorded in
`RunCondition.inner_lr_multiplier`.

### 3.3 The vendor has no tokenizer

`ttt/config.py:144` is the only tokenizer reference in the entire vendor tree, is
never read, and its Llama-2 default is stale — every model yaml declares Llama-3
(vocab 128256, bos 128000, eos 128001). So T2.1's instruction to "use the vendor
tokenizer at the pinned SHA" **has no referent**, and the length-matching
corruption it warned about is real but had to be avoided differently: work
entirely in token-ID space. `/train` and `/val` are flat 1-D ID streams, so a span
*is* real text by construction and length matching is exact in the units the
model consumes.

### 3.4 Two live defects in already-shipped code

- **`render_markdown` never printed the per-seed values** that `SpikeResult` has
  carried since the scaffold. A seed where the poison stream *helped* the victim
  was invisible in the only artefact anyone reads — a standing Rule 6 violation.
- **`cohens_d` returns ±inf** on zero pooled variance with differing means
  (`metrics.py:60-61`), and `exceeds` accepts `inf >= 0.8`. A stubbed harness, or
  fast weights that never moved, rendered **PROCEED** with an infinite effect
  size. Non-finite is now a hard FAIL.

### 3.5 The pre-registration claimed a guard that did not exist

`PREREGISTERED.md:64` lists "control not length/seed/**dtype**-matched to poison
(`RunCondition.assert_matches` guards this)" as an invalidating condition — and
there was no `dtype` field. `transformer.py:685` casts the whole model to
`state_dtype` per call, so dtype is load-bearing. Adding the field *satisfies* a
pre-registered claim rather than moving a bar.

### 3.6 A bug in my own windowed reduction

With `stride > max_length - 1` the window grid does not cover the sequence and
targets in the gaps were **never scored** — 15 of 32 in the case that exposed it.
Now rejected up front, plus a post-condition asserting every target from `1..n-1`
was scored exactly once. Both halves matter: too few understates coverage, twice
weights the overlap, and because the two arms differ in content either fault
biases the **ratio** rather than cancelling out of it.

### 3.7 Perplexity rewards repetition — a limitation of a pre-registered bar

Measured, not theorised: a repeated token pattern scores **1.90** where fluent
English scores **19.98**, because a repetitive stream is trivially predictable.

So the pre-registered ≤ 1.5 fluency bar **cannot** catch a poison stream that
reuses one passage many times — something no human would call benign-looking.
ADR-007 had flagged span multiplicity as an unmatched structural variable on
reasoning alone; this measurement is the evidence that drawing spans without
replacement and reporting multiplicity per arm are load-bearing rather than tidy.

## 4. Decisions taken, and why they are not bar-moving

All recorded before any result exists. Written afterwards, each would read as an
excuse.

**Span granularity (ADR-007).** `span_tokens` is an explicit parameter decoupled
from `mini_batch_size`, defaulting to 64. Chunk-sized spans would give the
attacker **8 units of choice per 8192-token window**, and a STOP under an 8-unit
lever could not be distinguished from "SELECT cannot corrupt fast weights". The
kill-gate is asymmetric — a false PROCEED costs a wasted Phase 2, a false STOP
costs everything — so this is biased toward the stronger attacker.

**Fluency aggregates as the max across seeds.** The pre-registration states the
bar as one number but the design has five streams. Under a mean, one seed at 3.0
is laundered by four at 1.1 *while that seed's loss still pools into the gated
Cohen's d*. Max is the strictest defensible reading, and Rule 5 exists to stop
bars being **loosened** — so the choice cannot be self-serving. The report prints
max, mean and the per-seed table with the worst seed marked, and if the verdict
turns on the aggregation it says so and demands a dated revision note before the
verdict is recorded.

**Verdict scope.** A STOP is scoped to **8K context with 8 inner SGD steps**, not
to TTT-E2E. ADR-005 records the mechanism's own benefit at 3B@8K as ~0.014 nats,
while the pre-registered ≥10% of ~2.3 nats is ~0.23 — roughly **16×** the entire
benefit at this context length. Corruption can exceed benefit, so the bar is not
impossible, but a STOP at 8K is evidence about 8K.

**Threshold source of truth.** Constants in `prereg.py` plus a CI test parsing
`PREREGISTERED.md` and asserting equality. Same guarantee as a runtime parse — a
bar cannot move without CI going red — but it fails at PR time rather than at the
end of a paid GPU run. Protocol rule **5b** was added because the parser is a new
surface on which a bar can move while the doc shows a clean diff.

## 5. The fluency reference model (T3.2)

**GPT-2 small**, independent of the victim on corpus (WebText vs DCLM+Books3),
tokenizer (50257 vs 128256), and the fact that it does not adapt at inference.
Independence is mechanical: the attacker optimises *against* the victim, so the
victim rates poisoned streams as maximally fluent and a bar scored with it would
pass every attack by construction.

`transformers` 5.x has **dropped Flax models entirely**, so the choice was a
deprecated `transformers` 4.x, torch as a second array framework, or implementing
the forward pass. Implemented, on the jax stack already present. The fluency path
therefore adds exactly two small lazily-imported runtime dependencies —
`safetensors` and `tokenizers`.

### The specified acceptance check does not work

T3.2 asked for a published perplexity as the acceptance check. GPT-2's WikiText-103
figure of **37.50** is per *word*, and the denominator is unspecified. The same
measured total NLL gives:

| Convention | Per-word perplexity |
|---|---|
| 204,464 whitespace words (post-detokenization) | **62.29** |
| 245,569 — WikiText-103's canonical token count | **31.18** |
| Published | **37.50** |

The published figure sits **between** the two conventions, so the check cannot
separate an implementation bug from a counting convention. It is recorded as
corroborating evidence, not used as a gate. Per-BPE-token perplexity is **22.659**,
squarely where GPT-2 small belongs.

### What establishes the implementation instead

Logit-level equivalence against HuggingFace's `GPT2LMHeadModel`:

| Sequence length | max \|logit diff\| | max \|NLL diff\| | argmax agreement |
|---|---|---|---|
| 1 | 1.373e-04 | 0 | 1.0000 |
| 7 | 1.984e-04 | 6.289e-05 | 1.0000 |
| 64 | 1.907e-04 | 7.823e-05 | 1.0000 |
| 256 | 2.213e-04 | 1.076e-04 | 1.0000 |
| 1024 | 5.798e-04 | 1.027e-04 | 1.0000 |

A transposed `Conv1D`, exact GELU instead of `gelu_new`, or a wrong LayerNorm
epsilon all shift logits by O(0.1) — four orders of magnitude outside this band.
`torch` and `transformers` are the yardstick, not the tool: declared in the
`verify` extra, imported by no code under `src/`.

Discrimination self-test (`--fluency-selftest`): fluent English **19.98**,
scrambled **1326.84** — a **66×** separation, checkable in one command on a fresh
box.

Full detail: `experiments/001-attack-spike/FLUENCY_REFERENCE.md`.

## 6. What is still blocked, and on what

**The one hard blocker is a purchase: the W&B entity, project and API key
(T1.2).** Every GPU task waits on it. `training.log_wandb=false` does not avoid
the login path — the vendor's `wandb.login` and an authenticated `api.runs()`
query run under an `is_master` guard and the result drives the resume decision —
and working around it means editing vendor code, which ADR-002 forbids.

**Three things need a person, not code:**

- **Review of the last branch.** `eval/fluency-reference` (T3.2) is the only
  unmerged work. The first wave was reviewed and merged by someone else during
  this period, satisfying rule 3.
- **The acknowledgement table** in `docs/protocols/branch-and-review.md` is still
  unsigned by all three people, even though merges have now happened against it.
  Worth closing so the protocol and the practice agree.
- **Inventorship (T3.9).** `docs/patent/invention-disclosure.md` still reads
  `TBD`.

**Remaining code work, in value order:**

1. **Bind `step_fn` to the real `MetaModel.inner_loop_step`**, plus `eval_benign`.
   ADR-006 settled the design and `carry.py` is tested, so this is the adapter
   plus the partition/combine dance. Possibly testable on CPU against a
   random-init 125M model with no checkpoint — needs checking, since `grain` may
   not ship a Windows wheel.
2. **`craft_stream` (T1.9)** — the adversarial search over the proposal space.
3. **PARAPHRASE and SOFT builders (T2.5)** — PARAPHRASE needs a text-side corpus
   and cannot work in ID space.
4. **T3.1's outstanding half** — push a deliberately broken commit, confirm CI
   fails, revert.
5. **T1.1** — commit the paper working tree (`docs/paper/`, still untracked).

## 8. The honest summary

Nothing has been measured. No GPU has been provisioned, no checkpoint fetched, no
dataset egressed, and the total spend is **$0** against a $325 cap.

What has been achieved is narrower and, for a project whose next step costs money
and whose verdict is irreversible, more useful: the experiment is now *runnable*,
its instrument is *validated*, and **five distinct ways of producing a
scientifically worthless answer have been found and closed** — three of them
routes to a false STOP that the numbers alone could never have revealed, one a
live PROCEED-from-degenerate-input bug, and one a bar that cannot detect the thing
it was written to detect.

The remaining risk is concentrated in one place: binding the carry overlay to the
real vendor model. Everything downstream of that is written and tested.
